# database-seeding Specification

## Purpose

Define el comportamiento del mecanismo de inicialización de datos para provisionar el consultorio activo y el usuario administrador inicial con hash Argon2 de forma idempotente mediante una configuración aislada.

## Requirements

### Requirement: Inicialización idempotente del consultorio activo
El comando de semilla `python -m app.seed` MUST insertar el consultorio base con el identificador explícito fijado en `CONSULTORIO_ACTIVO_ID` (soportado mediante `GENERATED BY DEFAULT AS IDENTITY`, DD-23) y sincronizar inmediatamente la secuencia de la tabla `consultorio` para que los nuevos registros utilicen valores superiores. Una ejecución sucesiva MUST detectar la existencia del consultorio sin modificarlo ni arrojar error.

#### Scenario: Creación de consultorio inicial en base limpia
- **GIVEN** una base de datos con las migraciones aplicadas y sin datos de consultorio
- **WHEN** se ejecuta el comando `python -m app.seed`
- **THEN** se crea el registro en `consultorio` con `id` igual a `CONSULTORIO_ACTIVO_ID`
- **AND** la secuencia `consultorio_id_seq` queda ajustada para evitar colisiones

#### Scenario: Ejecución idempotente con consultorio existente
- **GIVEN** una base de datos donde el consultorio `CONSULTORIO_ACTIVO_ID` ya existe
- **WHEN** se ejecuta nuevamente el comando de semilla
- **THEN** el comando finaliza con código 0 sin duplicar registros ni fallar

### Requirement: Provisión del usuario administrador inicial con Argon2
El comando de semilla MUST asegurar la creación de una cuenta de usuario con rol `administrador` asociada a `CONSULTORIO_ACTIVO_ID`, utilizando el correo especificado en `BOOTSTRAP_ADMIN_EMAIL`. La contraseña provista por el secreto o variable `BOOTSTRAP_ADMIN_PASSWORD` (o generada aleatoriamente si no se provee) MUST ser transformada a un hash Argon2 válido mediante `pwdlib`.

#### Scenario: Creación de administrador inicial con hash Argon2
- **GIVEN** una base de datos con el consultorio inicial creado pero sin usuarios
- **WHEN** se ejecuta el comando de semilla con `BOOTSTRAP_ADMIN_PASSWORD` y `BOOTSTRAP_ADMIN_EMAIL` provistos
- **THEN** se crea el usuario administrador con `password_hash` correspondiente a Argon2, `email_verificado=true`, y `aviso_privacidad_aceptado_en=None`

#### Scenario: Idempotencia ante administrador existente
- **GIVEN** el usuario administrador ya creado en el consultorio
- **WHEN** se ejecuta nuevamente el comando de semilla
- **THEN** el comando finaliza con éxito sin sobreescribir la contraseña ni duplicar el usuario

### Requirement: Configuración aislada de semilla mediante SeedSettings
El proceso de semilla MUST instanciarse cargando exclusivamente la clase `SeedSettings`, que hereda de la configuración de base de datos e incorpora únicamente `CONSULTORIO_ACTIVO_ID`, `APP_TIMEZONE`, `BOOTSTRAP_ADMIN_EMAIL` y `BOOTSTRAP_ADMIN_PASSWORD`, sin requerir secretos propios de la API como `JWT_SECRET_KEY` o claves de firma futuras.

#### Scenario: Ejecución sin secretos de la API
- **WHEN** se ejecuta `python -m app.seed` con base de datos, `CONSULTORIO_ACTIVO_ID` y contraseña de bootstrap pero sin `JWT_SECRET_KEY` ni `APP_ENV`
- **THEN** la semilla finaliza exitosamente con código 0

#### Scenario: Ejecución sin CONSULTORIO_ACTIVO_ID
- **WHEN** se intenta ejecutar la semilla sin `CONSULTORIO_ACTIVO_ID` en el entorno ni en secretos
- **THEN** la ejecución falla con mensaje de error claro indicando la variable requerida

### Requirement: La semilla inicializa el catálogo de prestaciones sin sobrescribirlo
El comando de semilla MUST asegurar nueve prestaciones iniciales por consultorio nuevo y repetirse sin duplicar ni reemplazar nombres, duraciones o activación de prestaciones ya existentes.

#### Scenario: Sembrar consultorio vacío
- **GIVEN** un consultorio activo sin prestaciones
- **WHEN** termina la inicialización de datos
- **THEN** quedan creadas nueve prestaciones iniciales con duraciones sugeridas

#### Scenario: Semilla repetida
- **GIVEN** el catálogo ya existe y el Administrador modificó una prestación
- **WHEN** se repite la semilla
- **THEN** los valores modificados se preservan y no se crean duplicados
